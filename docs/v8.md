# V.8 — Start-up session procedures (answering DCE)

Internal design, answerer side. Authority: ITU-T V.8; implementation reference
SpanDSP `src/v8.c` (`[REF]`).

## 1. Purpose

V.8 runs **before** any modem-specific training. It exchanges, over the V.21
channel 2 (answerer TX) / channel 1 (caller TX) FSK band, a set of messages
(CI/CM/JM/CJ) selecting the call function, modem modes available on each end, and
optional protocols. It also transmits the ANSam answer tone that V.8-capable
callers detect.

## 2. Signals

| Signal | Who sends | Tones / modulation |
|---|---|---|
| CNG | caller | 1100 ± 38 Hz, 0.5 s on / 3 s off (used by fax; a V.8 data caller typically does not send it) |
| CI | caller (ch1) | V.21 ch1 FSK, 300 baud, 10×1 preamble + async framed 0x00 + call-function octet |
| ANSam | answerer | 2100 ± 1 Hz, 20 ms AM at 15 ± 0.1 Hz. This implementation sends it WITHOUT phase reversals (see section 10) |
| CM | caller (ch1) | V.21 ch1 FSK: 10×1 preamble + framed 0xE0 sync octet + tagged information octets |
| JM | answerer (ch2) | V.21 ch2 FSK mirroring the CM |
| CJ | caller (ch1) | 3 consecutive zero octets (0x00,0x00,0x00) |

Tagged information octets in CM/JM (low 5 bits = tag):

```
0x01 call function
0x05 modulation modes (1-3 octets, extension indicated by bits 3-5 == 010)
0x0A protocols
0x0D PSTN access
0x0F NSF
0x07 PCM modem availability (V.90/V.92)
0x0E T.66
```

Modulation-mode bitmasks (V8_MOD_*): V.34HDX 0x80, V.34 0x40, V.90 0x20
(first octet); V.27ter 0x80, V.29 0x40, V.17 0x04, V.22 0x02, V.32 0x01
(second octet); V.21 0x80, V.23HDX 0x40, V.23 0x04, V.26bis 0x02, V.26ter 0x01
(third octet).

Message acceptance: a CI is accepted on a single clean copy; a CM/JM must arrive
twice identically to be accepted (`[REF]`).

## 3. FSK channel parameters (V.21 used by V.8)

From `[REF] src/fsk.c`:

| | ch1 (caller TX) | ch2 (answerer TX) |
|---|---|---|
| mark (logical 1) | 1180 Hz | 1850 Hz |
| space (logical 0) | 980 Hz | 1650 Hz |
| nominal baud | 300    | 300    |
| TX level | -14 dBm    | -14 dBm    |
| RX cut-off | -45.5 dBm | -45.5 dBm |

Async framing for V.8 messages: 1 start bit (0), 8 data bits LSB-first, 1 stop bit (1).
Preamble = 10 consecutive 1 bits before the sync octet.

Sync octets: CI → 0x00; CM/JM → 0xE0; V.92 → 0x55.

## 4. Answerer state machine

States follow the reference implementation but are re-mapped to the structure
required by this project (spec §10): every state names its input signal, the
detector used, the output signal, minimum/maximum duration, timeout and failure
behaviour.

```
V8_IDLE            -- call answered, media established
  -> V8_SEND_ANSAM -- immediately transmit ANSam (with phase reversal + 15Hz AM)
  -> V8_RX_CM
V8_RX_CM           -- listen on V.21 ch1 for CM (FSK detector + async framer)
        |  detector: FSK ch1 at 300 baud; accept after 2 identical frames
        |
        |  CM with no V.8 desired (non-V8 call) -> fall back to plain V.22bis:
        |      send ANS (2100/2225Hz) instead, proceed to modem-specific start
        v
  V8_SEND_JM       -- guard-tone-capable answerer: 75 ms silence then JM (V.21 ch2).
        |  answerer TX switches to ch2 for JM, still RX on ch1
        |  timeout Tm = 5000 ms waiting for CJ
        v
  V8_RX_CJ         -- receive 3 consecutive zero octets (0x00)
        |  detector: ch1 FSK + CJ pattern = 3 x (0x00 framed)
        v
  V8_SIGA          -- 75 ms silence, then V.8 negotiation complete.
        v
  V8_ENTER_MODE    -- invoke the selected modem module with V.8-selected params
```

Timers (authoritative V.8):
- Te (time for CI repeating from caller) = 500 ms minimum; reference uses 2×Te
  for the caller CI window. ANSam+75 ms before the answerer changes to JM.
- Tm = 5000 ms maximum awaiting CM by answerer (reference uses 200+5000).
- Post-JM wait for CJ = 5000 ms max.
- After CJ, wait 75 ms of silence, then hand over to the modem.

Guard tones: answerer option. Default AG = none (North America) or 1800 Hz / 550 Hz
per region. The answerer emits a guard tone only for the modem session (started
by the selected modem), not during V.8.

## 5. Detector requirements (spec §11, §32)

- ANSam is detected by the caller, not the answerer. The answerer does however
  verify the remote is sending CM (V.21 ch1 FSK) rather than just energy.
- The answerer RX runs three detectors simultaneously:
  1. ANSam/CNG tone RX (`[REF]` modem_connect_tones.c: 2100 Hz with AM 15 Hz →
     classifies ANS/ANSam; 1100 Hz → CNG). Not strictly needed for the answerer
     after V.8 but required to classify a non-V.8 caller (CNG → fax).
  2. V.21 ch1 FSK demodulator feeding the async bit framer.
  3. Power/envelope to detect break-in (end of CJ / modem start).

## 6. Message semantics for mode selection

After CM accepted, the answerer must advertise only modes its DSP actually
implements. The spanDSP reference echoes the received CM modulation list back
in the JM, which lets the caller select a mode this endpoint cannot run; the
build applies `spandsp-jm-modulations.patch` so the JM carries the configured
list (0x04 = V.22/V.22bis only). Selection preference on the caller side is
still:

```
V.92 > V.90 > V.34 > V.32bis(V.32) > V.22bis(V.22) > V.21
```

but with a V.22-only JM the caller cannot pick above V.22.

Call function must be 0x01 (V-series data modem: V8_CALL_V_SERIES); otherwise
terminate or fall back to non-V.8 procedure.

## 7. Verified connection flow (answer side, real hardware)

```
INVITE -> 200 OK -> AudioSocket established
-> tx plain ANSam (2100 Hz + 15 Hz AM) continuously
-> rx V.21 ch1: CM decoded after two identical copies
-> V8 handler: caller modulations = 0x1a16 (V.90,V.34,V.32,V.23,V.22,V.21)
-> JM sent with modulations = 0x04 (V.22 only, patched spanDSP)
-> caller sends CJ; 75 ms silence
-> enter V.22bis answerer: 75 ms silence then U11 on the 2400 Hz carrier
-> caller sends 1200 Hz carrier, then S1 (2400 request) after 155+456 ms
-> answerer detects S1 in a 32-symbol window, replies U0011, switches to 2400
-> both sides 16-way at 2400 bps, PPP up (10.67.0.1 <-> 10.67.0.2)
```

## 8. Failure behaviour

- No CM within Tm → V8 failing → fall back to non-V.8 V.22bis answer procedure
  (send ANS 2100/2225 Hz, wait for carrier) if allowed by config, else hangup.
- CM malformed repeatedly → same fallback.
- CJ never arrives → hangup after Tm.

## 9. Parameters to re-verify against current V.8 text before gold release

ANSam exact AM depth (30% nominal; reference uses a fixed AM index), ANSam
duration the answerer should sustain (until CM), guard-tone tables, NSF encoding
(`[REF]` flags NSF handling as TODO).

## 10. Implementation notes from real-hardware debugging

These findings come from captures of a real USB modem (Conexant CX93010)
dialing through a PAP2T ATA into `sm_sip`/`sm_daemon` (see
`tools/` and the analysis tools in the session notes). They explain every
non-obvious design decision above.

### 10.1 Plain ANSam, not ANSam/

The answerer originally sent ANSam with 180 degree phase reversals every
450 ms (`MODEM_CONNECT_TONES_ANSAM_PR`). That variant signals "V.92-capable
answerer", and the calling modem duly switched to the V.92 exchange: it sent
pairs of V.92 "CP" packets (V.21 ch1, sync octet 0x55, data byte 0x8C) every
~1.2 s and never sent its V.8 CM. spanDSP's answerer ignores CP packets, so
V.8 timed out and the modem gave up with NO CARRIER. Sending plain ANSam
(15 Hz AM only) makes the caller skip the V.92 exchange; it sends CM directly.
This is also the correct behaviour for a non-V.92 answerer per the V.8/V.92
start-up rules.

### 10.2 JM must advertise only implemented modes

spanDSP decodes CM into the same result structure it later serialises as JM,
so the JM echoed the caller's entire capability list (here 0x1a16 = V.90,
V.34, V.32, V.23, V.22, V.21). The caller then picked a high-speed mode and
started a start-up sequence this endpoint cannot answer (observed as a pure
1200 Hz hold tone after V.8). `spandsp-jm-modulations.patch` restores the
configured modulation list (V.22 only) before the JM is sent.

### 10.3 Post-V.8 handoff timing and S1 detection

After V.8 the answerer transmits U11 and the caller answers with an
unmodulated 1200 Hz carrier while its 155 + 456 ms timer runs, then sends the
100 ms S1 burst and scrambled ones. Two receiver adjustments make the 2400
handshake reliable:

- RX squelch of 500 ms after V.8 so symbol acquisition locks to the caller's
  own carrier rather than the leakage of our U11.
- S1 is detected over a sliding window of 32 symbols requiring >= 23
  (75 %) alternating symbols, instead of an unbroken run of 15. While the
  equalizer is still settling a few symbols demodulate wrongly; random data
  alternates only ~25 % of the time, so the window cannot false-trigger.

### 10.5 Analysis tools

The bit-level V.21 and V.8 replay tools used for this work are kept in
`tools/` (`v21demod.c`, `v8_replay.c`, `replay_rx.c`, `fftzoom.c`, ...).
`replay_rx` and the daemon both honour the `SM_RX_TRACE` environment variable,
which prints per-symbol raw bits from the V.22bis receiver and is off by
default.
