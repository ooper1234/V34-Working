# V.42 / V.42bis — internal technical design

Authority: ITU-T V.42 (error correction), ISO/IEC 8885 LAPM sub-procedure, ITU-T
V.42bis (data compression). Reference: SpanDSP `src/v42.c`, `src/v42bis.c`,
`src/hdlc.c` (`[REF]`).

## 1. Layering

```
pppd (serial bytes, async)
   |
 async byte framing (8N1)      <- serial/async
   |
 V.42bis compression (XID negotiated)
   |
 V.42 / LAPM (frames, CRC-16, window)
   |
 slip-mode? -> NO. The modem data channel carries the LAPM bit stream directly.
   |
 modem physical layer (our V.22bis/... TX-RX)
```

Key: V.42 runs above the modem modulation. In "direct" mode the modem delivers
the LAPM bitstream; in buffered/async the async-to-sync detection
("detection/sync detection procedure", Annex A of V.42) first detects whether the
remote uses error control. On a properly V.42 peer we negotiate LAPM; otherwise we
fall back to transparent async operation.

## 2. Detection and negotiation (V.42 §7, Annex A and B)

- Phase 1: modem connects (our modem layer reaches DATA).
- Phase 2: Detection — the answering DCE sends a V.42 "detect" sequence and listens
  for the caller's sequence; if the caller answers with SABME (or the calling
  pattern) we enter LAPM negotiation, else fall back to transparent async.
  Reference provides separate in-band negotiation via XID exchange.
- Phase 3: Negotiation — exchange XID frames for LAPM parameters: window size,
  I-field max length (N401 default 256 octets), retransmission count, compression
  (V.42bis) enable/disable and dictionary IDs, and octet/bit order.
- Phase 4: Data transfer with link supervision.

## 3. LAPM framing (ISO/IEC 7776/8885)

- HDLC address field A: single octet `0x03` (command 03 / response 01 unless
  two-octet EA mode).
- Control field: I (0x00.. info, N(S),N(R), P/F), S (0x01/0x05 etc: RR/RNR/REJ),
  U (0x03/0x0B/0x63/0x6B/0x6F/0xAF...: UI, DM, SABME, DISC, UA, XID, TEST, FRMR).
- Modulo 128 (default) sequence numbers, window K=7...K=127 negotiated in XID.
- FCS: CRC-16-CCITT (poly 0x1021, init 0xFFFF, negated) over address+control+info
  before zero-insertion.
- Zero-insertion: one 0 inserted after every run of five consecutive 1s in the
  transmitted bit stream (except the flag). Flag 0x7E, abort 0x7D? (abort is
  0x7D in single-bit sense: 01111101) — reference hdlc.c implements frame
  assembler/disassembler (see `[REF] src/hdlc.c`).

## 4. State machines

LAPM states (`[REF] src/v42.c`): IDLE, DISCONNECT_PENDING,
SETUP (awaiting UA), NEGOTIATION, NEGOTIATION_COMPLETE, DATA, DISCONNECT.
Timers (reference):
- T401 (SABME retransmit) ~ 1 s (`[REF]` "1 second between SABME's").
- T400 (whole negotiation) ~ 5-6 s; expires -> LAPM_V42_UNSUPPORTED (fall back).
- T403 (data transfer N(R) watchdog).

Command/response addressing; P-bit set on SABME/XR/DISC; F-bit on UA/DM.

## 5. Interface to our modem

Byte-stream API (not bit-level) between modem DATA mode and v42:

```
modem -> v42: put bytes (at line rate)
modem <- v42: get bytes
status: CARRIER_UP / CARRIER_DOWN / DATA_MODE / TRAINING_FAILED propagate to v42,
which discards in-progress frame on retransmit breach of N401 etc.
```

LAPM in/out is a continuous bit stream carried by the modem as its transparent
data. Our modem's DATA interface is already bit-oriented (modem data =
scrambled serial); we place LAPM bits onto it after async-to-sync framing in
buffered mode, or raw in bitstream mode. We implement bitstream (sync via flag) —
simplest, matches real-world modems with V.42.

## 6. V.42bis compression

- Dictionary-based; codewords 0x80+ assigned to strings; byte-oriented.
- Negotiated via XID ID=20 (`PI_V42BIS`); parameters: dictionary size (class),
  max string length, etc.
- Between LAPM and async layers: compress outgoing user data, decompress incoming.
- Reference `[REF] src/v42bis.c` uses SASL/stacked dictionaries. We will re-use the
  algorithm structure (self-defined implementation, not copied code).

## 7. Fallback

- If remote doesn't answer SABME/XID within T400/T401 retries → drop to
  non-error-controlled async at line speed (transparent mode). Telephony session
  still usable for a non-V42 peer (e.g. plain terminal).

## 8. Tests

- Fuzz: arbitrary byte streams in/out, verify no CRC escapes missed; flag abort
  handling; zero-bit insertion round trip.
- Loop: two LAPM instances across a bit-error channel (insert drops/errors), verify
  retransmit/in-order delivery.
- Remote: against a real dial-up modem's V.42 (Windows 95-era 14400 modem) once the
  V.22bis path connects.
